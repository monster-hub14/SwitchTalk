Release 16 build notes
Native Windows devkitA64 r28 / GCC 15.1.0, libnx 4.9.0, curl 7.69.1,
zlib 1.3.1, Opus 1.3. Application C uses -Wall -Wextra -Werror.

A single NRO contains the GUI, network worker, microphone test and call
engine. No resident service, pm:shell launch, IPC named-port controller,
Atmosphere ExeFS package, or startup flag is built or shipped.

The RTC archive is unchanged from Releases 10/13 (seeded DTLS RNG fix).
call.c retains the same transport, audio and cleanup code; its former
background-only compile option was removed and types/status text renamed.
The UI pauses the network worker before a call, stops and joins the call
worker before resuming it, and keeps password erasure at the same boundary.

The GUI owns a 1280x720 RGBA8, double-buffered libnx framebuffer with a
linear staging buffer. No console renderer is initialized in normal use.
A console fallback is used only if graphics initialization fails.
Rendering/hit testing is isolated from network and audio APIs. Font glyphs
are baked once; there is no runtime font service or extra renderer dependency.

Host suites cover graphical buffer bounds and hit testing plus the existing
API, polling, mic, PCM, call-session and DTLS initialization regressions.
The GUI previews are generated by compiling the actual UI source with
GUI_HEADLESS, using sample data. Physical Switch validation remains required.

Release 15 additions: saved_login.c uses the existing Mbed TLS AES-GCM library
plus libnx SPL and CSRNG services. No Nintendo key material is embedded or
exported. The key is derived with application-specific inputs and device-unique
option 1; generation 4 is fixed so firmware updates do not change the selected
key generation. Crypto service calls return errors without aborting the app.

stb_image is pinned at f0569113c93ad095470c54bf34a17b36646bbbb5. Only PNG/JPEG
and memory input are enabled. Downloads are limited to 512 KiB; dimensions to
1024x1024; decoder allocations to 16 MiB; cached images to 48 x 64x64 RGBA.
Source metadata additions enlarge TalkClient snapshots; the call algorithm
and its thread/stack configuration are unchanged. network.c retains its single
HTTP owner and cancellation/pause path; no second HTTP thread is introduced.

Saved-login tests use real Mbed TLS AES-GCM and fake hardware-derived keys;
therefore they validate file format, authentication, persistence and failures,
but not Switch SPL service access or actual cross-reboot hardware behavior.
Avatar HTTP tests mock the server; decoder tests use actual PNG/JPEG fixtures.
Preview photos are synthetic test fixtures, not the user's Nextcloud images.

Release 16 adds rich_text.c to the existing native frontend build. talk.c invokes the formatter in the shared message parse path. No new dependency is needed. All user data remains at the same paths and in the same format.
